# 캐릭터 스킨 · 중복 없는 뽑기

## 이용 방법

상점 → **스킨 뽑기** → **스킨 뽑기 · 10 Account Gold**를 누릅니다. 서버가 지급을 확정하면 빛이 퍼지고 전신 일러스트와 이름이 등장합니다. 결과에서 바로 장착하거나 인벤토리로 이동할 수 있습니다. 효과음은 기존 볼륨·음소거 설정을 따릅니다.

- 기본 0번 스킨 8종은 무료입니다. 게스트와 AI도 기본 얼굴 이미지를 사용합니다.
- 1·2번 스킨 총 16종이 뽑기 대상입니다. 보유하지 않은 스킨만 같은 확률로 등장합니다. 최초 각 6.25%이며 남은 수에 따라 화면에 확률이 표시됩니다.
- 1회 가격은 기존 기획의 10 Account Gold입니다. Run Gold나 RP는 사용하지 않습니다.
- 중복 지급이 없으며, 전부 수집하거나 잔액이 부족하면 구매할 수 없습니다.
- 인벤토리 → 캐릭터 스킨에서 **캐릭터마다 한 벌씩** 장착합니다. 기본 스킨으로 되돌릴 수 있습니다.
- 뽑기·인벤토리·전투 패널은 전신 PNG를 사용합니다. 전투에서는 중앙의 큰 일러스트 하단이 카드 뒤로 부드럽게 사라집니다. 캐릭터 선택·대기실·결과 화면은 `_crop.png`를 사용합니다. 대기실은 본인 장착 스킨과 다른 참가자의 기본 스킨을 표시하고, 원정 시작 시 확정된 장착을 모든 플레이어에게 공유합니다.
- 진행 중인 원정의 스킨은 시작 시점 상태로 고정합니다. 변경한 장착은 다음 원정에 적용됩니다.

## GitHub Pages 업로드

기존 index.html과 같은 위치에 **skin image 폴더 전체**를 올리고 **index.html 및 src 폴더 전체**를 덮어쓰면 됩니다. 폴더 이름의 공백과 파일명의 대소문자를 유지하세요. 전투 일러스트 확대 업데이트는 index.html, src/player-panels.css(신규), src/character-ui.js, src/cosmetics.js, src/skins.js를 함께 올려야 합니다. 서버 설정 변경은 필요 없습니다.

변경한 파일만 올릴 경우:

```text
src/account-ui.js
src/accounts.css
src/app.js
src/character-ui.js
src/cosmetics.js
src/skins.js         (신규)
src/skin-draw.js     (신규)
src/skin-reveal.js   (신규)
skin image/         (각 캐릭터 0·1·2 전신 + 얼굴 PNG, 총 48개)
```

계정 업데이트 자체를 아직 올리지 않았다면 [계정 업데이트 안내](ACCOUNT_UPDATE.md)의 전체 업로드 목록도 적용합니다. GitHub Pages 배포 완료 후 Ctrl+F5로 새 코드를 불러오세요.

## 서버 적용

2026-09-21 연결된 프로젝트 lktjmuhbfnahdghidqfa에 다음을 적용했습니다.

- migration `202609210005_skin_gacha.sql` 및 적용 이력.
- account-api의 `draw_skin` 요청 처리 배포.
- 기존 계정·랭킹·재화·카드 치장 구조를 유지하면서 캐릭터별 장착 JSON과 뽑기 영수증 테이블을 추가했습니다.

현재 프로젝트에 SQL을 다시 적용할 필요는 없습니다. 다른 서버에 설치할 때는 004까지 적용한 뒤 005를 순서대로 적용하고 account-api를 배포합니다. 기존 프로젝트의 초기 SQL이 수동 적용되어 있으므로 무작정 db push로 전체를 재실행하지 않습니다.

```powershell
npx.cmd supabase db query --linked --file supabase/migrations/202609210005_skin_gacha.sql
npx.cmd supabase migration repair 202609210005 --status applied --linked
npx.cmd supabase functions deploy account-api
npx.cmd supabase db query --linked --file supabase/check-skin-gacha.sql
```

골드 차감·추첨·지급·영수증은 같은 서버 트랜잭션 안에서 처리합니다. 동일 요청 번호의 재시도는 추가 차감 없이 기존 결과를 반환합니다. 클라이언트가 가격이나 당첨 스킨을 지정할 수 없고, 미보유 스킨 장착과 직접 DB 쓰기는 거부합니다.

네트워크 응답이 끊긴 경우 **이전 뽑기 결과 확인 / 재시도**로 같은 요청을 확인합니다. 브라우저 저장소를 사용할 수 있으면 새로고침 후에도 이어집니다. 저장소가 차단된 환경에서는 같은 페이지 안에서만 재시도 번호를 유지합니다. 이미 지급된 스킨은 인벤토리에 남습니다.

## 검증

36개 JS/TS 파일 문법·모듈 참조 검사와 자동 테스트 83개가 통과했습니다. 전체 24종 이미지 연결, UI 출력·연속 클릭 차단, 전투 얼굴 이미지, 권한·잔액·중복·재시도·전체 수집, 캐릭터별 장착 및 원정 스냅샷을 검사했습니다. 서버에서도 스킨 24종·기본 8종·뽑기 대상 16종, 서버 전용 추첨 권한과 원정 스킨 저장 트리거를 확인했습니다. 사용자 요청에 따라 실제 브라우저 플레이 테스트는 하지 않았습니다.

추가 스킨은 이미지 파일만 넣어서는 뽑기에 자동 등록되지 않습니다. src/skins.js의 목록과 shop_items의 서버 상품 등록을 함께 추가해야 합니다.
