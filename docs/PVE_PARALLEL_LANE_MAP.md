# PVE 병렬 경로 지도

## 확정 규칙

- 1층 10방, 2층 11방, 3층 12방을 진행한다. 이 수에는 보물방·휴식처·보스방이 포함된다.
- 공통 구간 사이에는 매판 3개 또는 4개의 경로를 생성한다. 각 경로는 같은 라인으로 계속 진행할 수 있다.
- 일반 구간에서 이웃 경로로 넘어갈 수 있는 연결부를 배치한다. 보물방 전후 각각 최소 두 깊이에 교차 이동을 제공한다. 한 깊이의 연결 방향을 통일해 X자 교차를 방지한다.
- 보물방은 중간 구간의 무작위 깊이에 한 개만 생성한다. 모든 경로가 그곳으로 합류하고, 다음 방에서 다시 전체 라인으로 갈라진다.
- 휴식처는 보스 직전 방에 한 개, 보스는 마지막 방에 한 개만 생성한다. 이 구간에도 모든 경로가 반드시 합류한다.
- 나머지는 일반 전투·이벤트·상점·엘리트 전투를 배치한다. 첫 방은 일반 전투다. 경로별 방 종류, 연결부 위치, 라인 수, 보물방 위치와 좌표가 시드에 따라 달라진다.

[참고: 인접 격자와 경로 연결을 이용한 절차적 맵 생성](https://dawninthemoon.tistory.com/95)

## 구현 및 호환

- map.js: 층별 기본 길이, 병렬 라인, 연결부 및 공통 합류 노드 생성.
- api.js: 서비스의 새 탐험 생성은 1층 10방으로 고정. 내부 테스트용 명시적 depthCount 인자는 유지한다.
- floor-transition.js: 새 2층/3층은 각각 11방/12방으로 생성.
- pve-roguelike-ui.js / pve-beta.css: 저장된 격자 좌표를 기존 지도 팝업에 표시한다. 전투 화면에 별도 패널을 추가하지 않는다. 기존 상단 진행 표시도 10/11/12개 방에 맞춰 폭을 조절한다.
- 모든 난수는 기존 시드와 RNG counter를 사용한다. 투표·재접속은 저장된 지도를 사용한다.
- 진행 중인 층의 지도를 덮어쓰지 않는다. 새 탐험과 이후 새로 생성되는 층부터 적용된다.
- 과거 column 없는 지도도 기존 좌표 배치로 표시한다. DB migration은 없다.

## 검증

- F1/F2/F3 각 1,000개, 총 3,000개 시드의 전체 경로 검사: 3개 이상 연속 라인, 인접 라인 이동, 공통 구간 필수 통과, 층별 10/11/12방, 막다른 길·고립 노드·X자 교차 없음.
- 같은 시드 재현, 서로 다른 시드의 경로/콘텐츠 다양성, 투표, JSON 재접속 및 public projection 확인.
- 기존 경로 회귀 테스트는 고정 깊이의 방 종류 대신 실제 연결된 경로에서 방 종류를 선택하도록 갱신. 쓰러진 캐릭터와 제출 완료 캐릭터는 테스트 자동 제출에서 제외.
- npm test: 2,357개 통과, 실패 0. npm run check: JavaScript/TypeScript 243개 문법 및 모듈/HTML 참조 검사 통과.
- smoke: T00/T02/T03/T04/T05/T06/T09/T14, 총 80개 시드, hard failure 0, failed seed 0. Balance warning 54건은 수치 변경 없이 기록한다.
- 실제 브라우저 테스트는 사용자 지시에 따라 수행하지 않았다.
