# 2026-09-22 동시 요청 오류 로그 수정

사용자가 제공한 supabase_logs.csv의 100개 기록 중 98개는 PostgreSQL 40001 / VERSION_CONFLICT입니다. 나머지 두 건은 HTTP 200 인증 확인입니다. 오류 기록은 한국 시간 2026-09-22 00:35:24.795~00:35:25.761, 약 0.97초에 집중되어 있습니다. 이 수치는 첨부 파일의 범위이며 전체 서버 오류 수를 의미하지 않습니다.

## 원인과 수정

동일한 방 버전을 읽은 두 요청 중 하나가 먼저 저장하면 다른 요청은 이전 상태를 덮어쓰지 않도록 거부됩니다. 기존 game_commit은 정상적으로 발생할 수 있는 이 충돌을 DB 예외로 발생시켰고, game-api는 간격 없이 최대 8회 다시 읽고 저장했습니다. 첨부된 로그는 이 충돌 오류입니다. 로그만으로 당시 플레이 중단이나 데이터 손상을 확인할 수는 없습니다.

또한 상태 조회 시 제출자 목록의 순서까지 비교하고 있었습니다. 실제 제출자가 같더라도 SQL 조회 순서가 달라지면 변경으로 판단해 방 상태를 저장하고 실시간 알림을 전송했습니다. 이를 참가자 집합 비교로 바꾸어 순서 차이는 저장·알림을 발생시키지 않도록 했습니다. 누락된 제출이나 잘못된 잠금은 기존처럼 복구합니다.

새 game_try_commit은 방 행을 잠근 뒤 버전을 검사합니다. 예상된 버전 충돌은 오류 대신 정상 응답으로 반환하고, 최신 방을 다시 읽어 처리합니다. 저장에 성공할 때는 같은 잠금 안에서 기존 트랜잭션을 실행하므로 카드·멤버·원정·보상·알림의 원자성과 최신 상태 보호를 유지합니다. 충돌 재시도에는 약 20~219ms의 증가하는 대기 시간을 두어 동시에 재요청이 몰리지 않게 했습니다. 최대 시도 횟수는 8회로 유지했습니다. 실제 DB 장애는 계속 오류로 처리합니다.
